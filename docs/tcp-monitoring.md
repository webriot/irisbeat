# TCP integration

Implements [#5](https://github.com/webriot/irisbeat/issues/5) under [spec #1](https://github.com/webriot/irisbeat/issues/1). Timing bounds and prospective edits follow [#3](https://github.com/webriot/irisbeat/issues/3); the Status ledger selection is recorded on [#2](https://github.com/webriot/irisbeat/issues/2).

`POST /api/operator/monitors` accepts `{ name, kind: "tcp", hostname, port, published?, intervalSeconds?, timeoutSeconds?, failureThreshold?, recoveryThreshold? }` and returns full operator status with 201. `PATCH /api/operator/monitors/:id` edits that Monitor; partial hostname/port edits retain the other target field. `hostname` is a DNS name, IPv4 address or IPv6 literal; `port` is an integer 1–65535. The collection operator form offers HTTP(S), TCP and Heartbeat, while retaining publication and timing controls. Operator reads return `kind` and only its target fields. Anonymous API and HTML omit targets. HTTP configuration remains compatible with omitted `kind` and a credential-free HTTP(S) `url`. Stored Monitors without a kind read as HTTP; no existing observations or Incidents change. The legacy `PUT /api/operator` target form and first-visible `monitor` response alias remain available alongside `monitors[]`.

Monitor kind is fixed after creation in API and UI, as confirmed by the owner on #5. Type changes return 400 without saving other fields. Target edits retain ID/detection/history and affect later attempts; an active attempt uses its starting target.

Sibling handoff: the target discriminator and fields belong to each Monitor, alongside timing, rather than context settings. `Target` is the HTTP/TCP/Heartbeat union in `src/index.ts`; `parseConfiguration` validates it and `checkMonitor(id, at)` snapshots the starting Monitor before I/O. Native `connect({ hostname, port })` waits for `opened`, races the configured deadline, handles `closed` rejection and requests closure in `finally`. Cleanup runs through the Durable Object lifetime without delaying observation commits or future dispatch; synchronous throws and rejected cleanup are handled. Stored IPv6 literals remain unbracketed and gain brackets at the native socket boundary. The existing detection transaction handles all three kinds. No extra binding, credential or container is needed.

The [collection handoff](monitor-api.md) and [Heartbeat handoff](heartbeat-api.md) are integrated through `3b524d867c6d77625fb00ad0fe02722cb128a49e` (#2/#3/#4/#6/#7), merged into TCP `f7a19c714664be3bf0ae6132829b97698d45b04a`. Creation order, per-ID guards/Incidents, publication-independent checks and alerts, and deleted-Monitor late-result discard apply to all three kinds. #7's destination stays context-level; shared post-transaction delivery handles each Monitor's named transition. Page/Monitor saves preserve the destination and emit no alert. Single-Monitor TCP, Heartbeat and kind-less HTTP collection upgrades retain identity, detector progress, timing and Incidents. Heartbeat additionally retains freshness and recovery spacing anchors.

ID-specific PATCH parsing stays inside the DO with mutation; partial hostname/port edits cannot overwrite concurrent changes. Legacy saves pin the first ID before reading the body: stale identity returns 409; changed kind returns 400; neither saves page or Monitor settings. Kind-specific validation rejects foreign target/timing fields atomically. Heartbeat ingress authorizes before dispatch, ignores bodies and rejects HTTP/TCP/deleted IDs without changing state.
