# TCP integration

Implements [#5](https://github.com/webriot/irisbeat/issues/5) under [spec #1](https://github.com/webriot/irisbeat/issues/1). Timing bounds and prospective edits follow [#3](https://github.com/webriot/irisbeat/issues/3); the Status ledger selection is recorded on [#2](https://github.com/webriot/irisbeat/issues/2).

`POST /api/operator/monitors` accepts `{ name, kind: "tcp", hostname, port, published?, intervalSeconds?, timeoutSeconds?, failureThreshold?, recoveryThreshold? }` and returns full operator status with 201. `PATCH /api/operator/monitors/:id` edits that Monitor; partial hostname/port edits retain the other target field. `hostname` is a DNS name, IPv4 address or IPv6 literal; `port` is an integer 1–65535. The collection operator form offers HTTP(S) and TCP, while retaining publication and timing controls. Operator reads return `kind` and only its target fields. Anonymous API and HTML omit targets. HTTP configuration remains compatible with omitted `kind` and a credential-free HTTP(S) `url`. Stored Monitors without a kind read as HTTP; no existing observations or Incidents change. The legacy `PUT /api/operator` target form and first-visible `monitor` response alias remain available alongside `monitors[]`.

Kind changes remain supported by API and UI to preserve the earlier TCP slice's behavior. Immutable kind is pending owner decision. Switching requires a valid target for the new kind, clears inactive target fields, preserves ID/detection/history and affects later attempts; an active attempt uses its starting kind and target.

Sibling handoff: the target discriminator and fields belong to each Monitor, alongside timing, rather than context settings. `Target` is the HTTP/TCP union in `src/index.ts`; `parseConfiguration` validates it and `checkMonitor(id, at)` snapshots the starting Monitor before I/O. Native `connect({ hostname, port })` waits for `opened`, races the configured deadline, handles `closed` rejection and requests closure in `finally`. Cleanup runs through the Durable Object lifetime without delaying observation commits or future dispatch; synchronous throws and rejected cleanup are handled. Stored IPv6 literals remain unbracketed and gain brackets at the native socket boundary. The existing detection transaction handles both kinds. No extra binding, credential or container is needed.

The [collection handoff](monitor-api.md) is integrated from `integration/spec-1` at `1e73abc32bd6e927ee7f3b052faa7a761a466673` (#2/#3/#4/#7). Creation order, per-ID guards/Incidents, publication-independent checks and alerts, and deleted-Monitor late-result discard apply to both kinds. #7's destination stays context-level; shared post-transaction delivery handles each Monitor's named transition. Page/Monitor saves preserve the destination and emit no alert. Single-Monitor TCP and kind-less HTTP collection upgrade paths retain target, identity, detector progress, due times and Incidents.

`test/tcp.test.ts` exercises real Worker HTTP requests, scheduled dispatch and SQLite Durable Objects with substituted native sockets and controlled deadlines. It covers persistence/defaults, target privacy, connection success/refusal, timeout cleanup/recovery, active-attempt snapshots, interval rescheduling, atomic validation and the operator controls. Mixed collection cases also cover independent failures/recovery, per-ID partial targets/edits and active snapshots, publication/privacy, pending-socket deletion, webhook identity, eviction and compatibility kind changes. No storage/private-method assertions, live customer connections, browser automation or deployment.
