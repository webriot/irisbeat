# TCP integration

Implements [#5](https://github.com/webriot/irisbeat/issues/5) under [spec #1](https://github.com/webriot/irisbeat/issues/1). Timing bounds and prospective edits follow [#3](https://github.com/webriot/irisbeat/issues/3); the Status ledger selection is recorded on [#2](https://github.com/webriot/irisbeat/issues/2).

`PUT /api/operator` accepts `{ pageName, name, kind: "tcp", hostname, port, intervalSeconds?, timeoutSeconds?, failureThreshold?, recoveryThreshold? }`. `hostname` is a DNS name, IPv4 address or IPv6 literal; `port` is an integer 1–65535. Operator reads return `kind` and only its target fields. Anonymous API and HTML omit targets. HTTP configuration remains compatible with omitted `kind` and a credential-free HTTP(S) `url`. Stored Monitors without a kind read as HTTP; no existing observations or Incidents change.

Sibling handoff: the target discriminator and fields belong to each Monitor, alongside timing, rather than context settings. `Target` is the HTTP/TCP union in `src/index.ts`; `parseConfiguration` validates it and `check` snapshots the starting Monitor before I/O. Native `connect({ hostname, port })` waits for `opened`, races the configured deadline, handles `closed` rejection and force-closes in `finally`. The existing detection transaction handles both kinds. No extra binding, credential or container is needed.

The [collection handoff](https://github.com/webriot/irisbeat/blob/t3/multiple-monitors-operator-controls/docs/monitor-api.md) was read while #18 remained unmerged. When collections reach integration, carry the target union into Monitor create/edit validation, operator serialization and per-ID attempts; use its ID-based CRUD and ledger UI. Keep publication independent of checks, preserve per-ID Incident lookups and discard deleted-Monitor results. #7's webhook support was merged from integration at `e0bfa2b`; its destination remains context-level and the shared post-transaction delivery handles either target kind. TCP transition coverage verifies exactly one named opening and recovery alert, without alerts on edits.

`test/tcp.test.ts` exercises real Worker HTTP requests, scheduled dispatch and SQLite Durable Objects with substituted native sockets and controlled deadlines. It covers persistence/defaults, target privacy, connection success/refusal, timeout cleanup/recovery, active-attempt snapshots, interval rescheduling, atomic validation and the operator controls. No storage/private-method assertions, live customer connections, browser automation or deployment.
